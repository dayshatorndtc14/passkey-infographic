How it works

หลักการ "กุญแจ 2 ดอก"

ตัดระบบกรอกรหัสผ่านทิ้ง ใช้ Cryptography (การเข้ารหัสลับ) แทนที่ทั้งหมด

🗝️ กุญแจส่วนตัว (Private Key)

ฝังอยู่ในชิปเครื่องเรา

เก็บใน TPM (Trusted Platform Module: ชิปความปลอดภัยบนเมนบอร์ด) หรือ Password Manager ปลดล็อกด้วยสแกนนิ้ว/ใบหน้า ไม่เคยส่งออกไปไหนเด็ดขาด

🔓 กุญแจสาธารณะ (Public Key)

อยู่ที่เซิร์ฟเวอร์เว็บ

เซิร์ฟเวอร์เก็บเฉพาะกุญแจไข ต่อให้เซิร์ฟเวอร์โดนแฮก แฮกเกอร์ก็ไม่ได้รหัสผ่านเราไป

🛡️ ป้องกัน Phishing 100% — ถ้าเป็นเว็บปลอม เบราว์เซอร์จะไม่ยอมส่งกุญแจให้
💡 หมายเหตุ: TPM (Trusted Platform Module) = ชิปฮาร์ดแวร์ความปลอดภัยบนเมนบอร์ด ใช้สร้างและเก็บกุญแจลับเฉพาะเครื่อง ป้องกันการขโมยข้อมูลระดับฮาร์ดแวร์
The Big 3 Tools & Comparison

3 สไตล์ 3 ปรัชญาการเก็บ Passkey

เปรียบเทียบจุดแข็ง & ข้อจำกัด ของเครื่องมือยอดนิยมในหน้าเดียว

Windows Hello

OS Native

ปรัชญา: ฝังในชิป TPM (Trusted Platform Module) บนเมนบอร์ด ล็อกอินด้วยสแกนนิ้ว/ใบหน้า/PIN

✅ จุดเด่น: เร็วที่สุด สแกนนิ้ว 1 วิ, ฟรีในตัว Windows, ไร้รหัสผ่านหลุดทางเน็ต
⚠️ ข้อจำกัด: ผูกติดกับคอมเครื่องนั้น (ย้ายเครื่องต้องตั้งค่าใหม่)

Bitwarden

Cloud E2EE

ปรัชญา: ซิงค์ข้ามทุก OS (PC, Mac, iOS, Android) ด้วยการเข้ารหัส E2EE (End-to-End Encryption)

✅ จุดเด่น: คล่องตัวสูงสุด ซิงค์ได้ทุกเครื่อง ทุกเบราว์เซอร์, แชร์ในทีมได้
⚠️ ข้อจำกัด: ต้องต่อเน็ตเพื่อซิงค์, ต้องรักษา Master Password ให้รัดกุม

KeePassXC

100% Offline

ปรัชญา: Open-Source เก็บเป็นไฟล์ฐานข้อมูล .kdbx ในเครื่องตัวเอง ไม่พึ่งพา Cloud

✅ จุดเด่น: ไพรเวตและปลอดภัยสูงสุด 100% ไร้คลาวด์, เราคุมกุญแจเองทั้งหมด
⚠️ ข้อจำกัด: ซิงค์แบบ Manual (ก๊อปไฟล์เอง), ต้องดูแลการ Backup เอง
💡 หมายเหตุ: TPM = ชิปความปลอดภัยบนเมนบอร์ด | E2EE = เข้ารหัสต้นทางถึงปลายทาง คลาวด์อ่านไม่ได้ | PIN = รหัสตัวเลขปลดล็อกเฉพาะเครื่อง

Best Practices & Safety Net

3 ข้อควรจำ ก่อนเริ่มใช้ Passkey

Passkey ปลอดภัย 100% แต่ต้องเตรียม "แผนสำรอง" ป้องกันการติดล็อกเมื่ออุปกรณ์ชำรุดหรือสูญหาย

📱
🔑 ปั๊มกุญแจสำรอง

1. ผูกอุปกรณ์สำรอง

• ปัญหา: คอมฯ ตกน้ำ เมนบอร์ดพัง ชิป TPM เสีย กุญแจในเครื่องจะหายทันที
• วิธีแก้: ผูก Passkey ไว้ที่คอมฯ (ดอกที่ 1) + มือถือหรือ Bitwarden (ดอกที่ 2)
• ผลลัพธ์: คอมพัง ยังใช้มือถือสแกน QR Code เข้าบัญชีได้ทันที

💾
📄 สำเนาไฟล์ตู้เซฟ

2. สำรองไฟล์ Database

• ปัญหา: KeePassXC ออฟไลน์ 100% ไม่มี Cloud คอย Backup ให้อัตโนมัติ
• วิธีแก้: ก๊อปปี้ไฟล์ .kdbx เก็บใน Flash Drive หรือ External Drive สำรอง
• ผลลัพธ์: ฮาร์ดดิสก์พัง แค่เอาไฟล์สำรองมาเปิดบนเครื่องใหม่ก็จบ

🔐
🚪 กุญแจฉุกเฉิน

3. เก็บ Recovery Codes

• ปัญหา: เผื่อเกิดเหตุสุดวิสัย โน้ตบุ๊กพังพร้อมกับทำมือถือหายพร้อมกัน
• วิธีแก้: เปิด 2FA สำรอง และจดบันทึก Recovery Codes (8-10 หลัก) ไว้ในที่ปลอดภัย
• ผลลัพธ์: มี "ไพ่ใบสุดท้าย" ปลดล็อกกู้บัญชีคืนได้ 100% ไม่ติดล็อกถาวร

💡 หัวใจสำคัญ: Passkey ปลอดภัยจากแฮกเกอร์ 100% แต่เราต้องเตรียม "ทางเข้าสำรอง" เผื่อเราทำอุปกรณ์ตัวเองพังหรือสูญหาย
Summary & Security Architecture

Passkey มาตรฐานความปลอดภัยใหม่
ที่ ปิดตายทุกช่องโหว่เดิม

สถาปัตยกรรมความปลอดภัย 3 ระดับ (Zero Shared Secrets & Phishing-Proof)

1. ต้นทาง (Client)
💻🔐
ไม่มีรหัสผ่านให้หลุด

เก็บ Private Key เฉพาะในเครื่อง ไม่เคยส่งออกทางเน็ต และไม่มีรหัสผ่านให้เผลอกรอก

🛡️ Key ไม่เคยออกจากเครื่อง
ตรวจ Domain ➔
2. ตรงกลาง (Browser)
🌐🛡️
ล็อกส่งเฉพาะเว็บจริง

ระบบตรวจ Origin Binding อัตโนมัติ หากเจอเว็บปลอม/Phishing จะตัดการเชื่อมต่อทันที

🚫 เว็บปลอมหลอกไม่ได้ 100%
ส่งแค่ Signature ➔
3. ปลายทาง (Server)
☁️🔒
ไม่มีรหัสผ่านให้แฮก

เก็บบนคลาวด์แค่ Public Key ต่อให้ฐานข้อมูลถูกเจาะ แฮกเกอร์ก็ไม่มีรหัสผ่านให้ขโมย

✅ ไร้ Shared Secret
"ต้นทางไม่มีรหัสผ่านให้หลุด — ตรงกลางล็อกส่งเฉพาะเว็บจริง — ปลายทางไม่มีรหัสผ่านให้แฮก"
